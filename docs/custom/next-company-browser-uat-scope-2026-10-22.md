## Selection and non-interference rules

1. **Default website UAT:** use the designated company Edge through the existing, authorized browser integration when available; preserve the current Edge Profile, don't relaunch with new debugging flags, don't overwrite login state or open/inspect unrelated tabs. For a UAT that creates pages, use a scoped page and clean up only resources it owns. Take no destructive CMS action without the specific task's authorization.
2. **Default GitLab:** use connected `gitlab` API MCP (Token handled by the connector; never expose it, copy it into code/config, or paste it into browser URL). For pipelines/MRs/branches, query API first. If the API lacks a necessary UI-only operation, perform an explicit scoped browser operation against `https://gitlab.oprueba.com` in designated Edge with approval, not a general browser fallback.
3. **Native NEXT Broker readiness:** current installed NEXT RC5 native Browser catalog remains 0 connected profiles/policies. Its **source** HEAD `8ef0d9d5` has a safe, Next-only read-only policy-file loader; it is **not yet installed** in RC5. Do not write live `${HOME}/.agentdock-next/browser-routes.json` until the actual connector-to-Broker transport/canonical endpoint is resolved and per-root origin policy is validated. No global `launchctl setenv`, no manually patched signed `.app`, no copying original AgentDock/Edge secrets.
4. **Separation and fail-closed:** company domain routing must not silently fall back to Managed Chrome when Edge/authorization is unavailable. Avoid adding broad wildcard origins or granting the content-CMS root unrestricted access to the whole enterprise. Explicit profile/CDP health, consent and per-task scope still govern connection and operations.

## 2026-10-22 NEXT native admission integration finding

- Audited `internal/app/runtime.go` and `internal/tool/browser/route_planner.go` against the standalone `edge-devtools-profile-ws`: **production Runtime constructs `NewRoutePlanner(..., nil)`** for the external connector status provider. `route_planner.go` requires an opaque, one-time qualified observation to authorize external routing; it documents that no production attestor exists. `external_pinned_connector.go` explicitly labels the pinned, source-only relay **without production callers** or an `externalTransportFence`. The present Broker cannot simply import Stable's working WebSocket MCP as a verified native Edge provider; doing so would bypass essential owner/lease/consent/transport invariants.
- A new **offline cross-layer regression** `internal/app/next_browser_external_route_admission_darwin_test.go` uses the real NEXT owner-only `browser-routes.json` parser, a synthetic but structurally valid company Oprueba/HomiPlay route, and the real planner. Even with matching company Edge catalog/policy and a fake provider claiming `Healthy=true`, `Verified=true`, `Authenticated=true`, `Resolve` must fail with `REQUIRED_ROUTE_UNAVAILABLE` without the trusted attestor. No Edge connection, processes, browser pages or credentials participate. This is an intentionally fail-closed product acceptance check, **not** a successful live Edge UAT.
- The smallest safe enablement cannot be only a JSON setting: design and test a **NEXT-owned**, auditable connector status/attestation service and bounded transport fence; bind verified Edge process/profile/endpoint to user consent, exact workspace root and HTTPS origins, single owner lease and cleanup. Only then connect it to the existing private route reader and provision NEXT's own connector lifecycle. Do **not** register unrestricted `chrome-devtools-mcp` directly as a substitute for that Broker, and do not copy Stable's standalone MCP registry or OAuth/token credentials into NEXT.
- GitLab REST/MCP API remains first choice for pipelines, commits and MRs. Stable's existing GitLab connector works; NEXT registration must use independently authorized OAuth/token workflow, rather than copying Stable credentials. GitLab web UI is allowed only for task-scoped browser-only checks.
