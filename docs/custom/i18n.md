# Internationalization Architecture

> 狀態：Architecture baseline

## 1. 目標

i18n 必須同時滿足：

- macOS / Windows / Shared UI 共用來源。
- locale 清單不寫死在 Swift、C#、Vue 或 Python。
- 志願貢獻者不需要理解程式碼即可新增或更新翻譯。
- Git diff 容易 review。
- placeholder、plural、fallback、coverage 可被 CI 驗證。
- generated native resource 不需要人工同步。

## 2. Canonical Source

建議 repo-level：

```text
i18n/
├─ manifest.yaml
├─ glossary.yaml
├─ README.md
├─ schema/
│   └─ messages.schema.json
└─ locales/
    ├─ en.yaml
    ├─ zh-Hant.yaml
    └─ zh-Hans.yaml
```

英文是 canonical source 與 fallback。

初期正式語系：

- `en`
- `zh-Hant`
- `zh-Hans`

架構完成後再開放更多 volunteer locale。

## 3. Locale Manifest

示意：

```yaml
locales:
  - code: en
    nativeName: English
    fallback: null
    direction: ltr
    status: stable

  - code: zh-Hant
    nativeName: 繁體中文
    fallback: en
    direction: ltr
    status: stable

  - code: zh-Hans
    nativeName: 简体中文
    fallback: en
    direction: ltr
    status: stable
```

UI 的語言選單應由 manifest 衍生，不另外維護 hard-coded enum。

Locale code 使用 BCP 47-compatible naming，平台需要不同 tag 時由 generator 做 mapping。

## 4. Message Format

AI 圓桌曾在 JSON 與 YAML 之間有明確分歧：

- JSON 的優點是 parser / schema / TMS tooling 一致，Go 與 TypeScript 都能直接處理。
- YAML 的優點是 translator comment、可讀 diff 與純文字志願翻譯體驗較好。

本專案最後採用 **嚴格受限的 YAML authoring format**，並在 build / TMS 邊界產生 JSON 或各平台 native resource。也就是 YAML 只負責「人類編輯」，不是 runtime contract。

Canonical translation：

```yaml
# Displayed when a newer ACP adapter package is detected.
acp.update_available: "Update available: {version}"

browser.mode.isolated: "Isolated browser"
settings.language.follow_system: "Follow system"
```

YAML 的目的不是 runtime optimization，而是讓 volunteer：

- 易讀
- 易寫
- 可以加入 translator comment
- 可以直接在 GitHub PR review

Runtime 使用 build-time generated assets。

### Strict YAML Profile

為避免 YAML 常見的隱式型別與 ICU 大括號問題，locale catalog 必須限制在可預測子集：

- YAML 1.2。
- message value 一律使用雙引號 scalar。
- 禁止 anchor / alias / merge key / custom tag。
- 禁止 flow mapping / flow sequence。
- locale catalog 禁止 block / folded multiline scalar；換行使用明確的 `\n`。
- key 與 value 都必須是 string。
- parser 讀取後必須再通過 schema 與 message validator。

例如：

```yaml
good.message: "Processed {count} files."
```

不允許：

```yaml
bad.message: {count}
another.bad.message: >
  multiline text
```

如果未來接 Crowdin、Weblate、Phrase 等 TMS，可由 canonical catalog deterministic export 為 JSON / ICU，再將翻譯結果經 validator 匯回；不要求 TMS 直接 round-trip YAML 格式。

## 5. Key 規則

使用 semantic namespace：

```text
common.*
runtime.*
connection.*
settings.*
browser.*
acp.*
activity.*
task.*
permission.*
mcp.*
plugin.*
update.*
error.*
```

禁止 `button1`、`label2` 等 layout-based key。

## 6. Generated Artifacts

```text
YAML source
   │
   ├─ Shared UI catalog
   ├─ macOS Localizable.strings
   ├─ macOS InfoPlist.strings
   ├─ Windows resources
   └─ installer resources
```

Generated file 必須標記：

```text
GENERATED FILE — DO NOT EDIT
```

generator 應 deterministic，CI 驗證 repo 中 committed generated files 沒有 stale。

## 7. ICU MessageFormat / Placeholder / Plural

Canonical message syntax 採 **ICU MessageFormat contract**。

簡單字串不需要複雜語法：

```yaml
common.save: "Save"
```

有參數時：

```yaml
acp.update_available: "Update available: {version}"
```

需要 plural / select 時才使用相應 ICU expression。也就是先固定可跨語系驗證的 contract，不要求所有字串一開始就使用 plural/select。

所有 locale 必須保持與 English source 相同的 placeholder set。

例如：

```text
Version {version}
```

不得翻成遺失 `{version}` 的字串。

CI 必須解析 ICU message，而不是只用 regex 比較大括號。不同 locale 的 argument name 與 argument kind 必須相容。

各 runtime 不應自行發明另一套 interpolation syntax；Shared UI / native resource 若不能直接執行 ICU，應由 generator 或共用 formatting layer 做轉換。

## 8. Locale Status

```text
draft
beta
stable
```

新語系不要求第一次 PR 就 100%。

Fallback：

```text
missing locale key
→ English
```

Stable locale 可設定較高 coverage gate；draft / beta 允許逐步補齊。

## 9. CI

至少檢查：

- YAML / schema validity
- duplicate key
- unknown key
- missing canonical key
- locale code validity
- fallback loop
- placeholder mismatch
- ICU syntax / argument-kind mismatch
- generated assets up-to-date
- translation coverage
- user-facing hard-coded string scan

CI 應輸出 coverage，例如：

```text
en       100% stable
zh-Hant  100% stable
zh-Hans  100% stable
ja        72% beta
```

## 10. Volunteer Workflow

理想新增語系流程：

1. 複製 `i18n/locales/en.yaml`。
2. 重新命名為 locale code。
3. 翻譯 value，不修改 key。
4. 在 `manifest.yaml` 新增 locale metadata。
5. 執行單一 i18n validation command。
6. 提交 PR。

Volunteer 不應修改：

- Swift enum
- C# constants
- Vue locale switcher
- Python locale tuple
- native resource XML / strings

## 11. Existing Translation Migration

建立新 i18n foundation 時，不重新手工翻譯目前 AppKit / WPF 已有內容。

應先建立 migration/import tool：

```text
macOS .strings
Windows .resx
       │
       ▼
key/value inventory
       │
       ▼
canonical en / zh-Hans / existing zh-Hant candidates
```

同義但 key 不同的字串由人工 review 合併；工具不得猜測語意後自動丟棄任何 existing translation。

## 12. Glossary

`i18n/glossary.yaml` 記錄產品術語：

```yaml
ACP:
  translate: false

MCP:
  translate: false

workspace:
  zh-Hant: 工作區
  zh-Hans: 工作区
```

Glossary 是 review reference，不應成為另一個完整 message catalog。

## 13. Hard-coded Text Policy

新 user-facing string 必須走 i18n key。

合理例外：

- debug log
- machine-readable error code
- protocol identifier
- test fixture

使用者可看到的錯誤訊息不屬於例外。
